# README direto

Escreva um README que o usuário possa publicar como seu: simples, concreto e
sem tom promocional. O usuário prefere ir direto ao ponto. Preserve essa
naturalidade com português correto; não imite erros de digitação, abreviações
de chat ou informalidade forçada.

## Conteúdo

Leia o README existente e os arquivos relevantes antes de escrever. Identifique
o que o projeto faz, como usá-lo e quais limitações afetam esse uso. Confira os
comandos no próprio projeto. Não invente instalação, funcionalidades, resultados
de testes, suporte a plataformas ou planos futuros.

Abra com uma frase que explique o projeto e sua finalidade. Em configuração
pessoal, "Minha configuração do Neovim para programação e estudo" soa melhor
que uma apresentação institucional. Use primeira pessoa quando combinar com
a autoria e o contexto; não force esse tom em um projeto de equipe.

Comece pequeno. Acrescente instalação, execução, pré-requisitos, exemplos ou
limitações somente quando o leitor precisar deles. Um projeto complexo pode
exigir um README maior. Não sacrifique instruções necessárias para caber em
um limite artificial de palavras.

Prefira frases curtas, verbos diretos e detalhes verificáveis. Evite adjetivos
como "robusto", "poderoso", "completo" e "intuitivo" quando não informam nada.
Não use slogans, emojis decorativos, badges sem utilidade, resumo conclusivo
nem uma seção para cada frase. Não explique Git, terminal ou editor do zero
quando o público já usa essas ferramentas.

Use listas para itens paralelos e blocos de código para comandos. Use tabelas
apenas quando facilitarem a consulta, como uma lista curta de atalhos.
Em revisões, preserve links úteis, avisos necessários, licenças e atribuições.
Leve detalhes extensos para documentos existentes e aponte o link, sem criar
uma árvore de documentação só para encurtar o README.

## Referência de tom

Evite:
"Uma solução robusta e altamente personalizável que transforma sua experiência
de desenvolvimento com ferramentas modernas e uma integração poderosa de IA."

Prefira:
"Minha configuração do Neovim para programar, escrever em LaTeX e fazer
anotações. Uso o Codex em um terminal lateral."

O exemplo orienta o tom; não copie seus fatos para outros projetos.

Antes de entregar, corte frases que repetem o título, listas já explicadas e
comentários sobre o processo de escrita. A abertura precisa deixar claro o
que é o projeto, e as instruções precisam permitir o uso real. Entregue o
texto ou a alteração solicitada, sem um relatório de estilo não solicitado.
